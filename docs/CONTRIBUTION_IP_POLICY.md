# Korako Contribution & IP Policy — Interim v0.1

**Status:** interim public-collaboration boundary  
**Applies to:** `vcheeko/korako-yolawani`

Korako Yolawani is publicly visible, but this repository does **not** currently include an open-source `LICENSE` file.

## Interim rule

Until a formal company, contributor-license and commercialization structure is adopted:

- public review, issue reports, reproducibility feedback, benchmark proposals and documentation corrections are welcome;
- small public-proof fixes may be considered case by case;
- substantial third-party code, reusable product IP or private-runtime implementation should **not** be submitted or merged;
- contributors must not submit material they do not have the right to contribute;
- public contributions must stay inside the documented public/private boundary;
- accepting a contribution does not grant access to the private KORA/Korako runtime or transfer ownership of Korako's private IP.

## Why this interim boundary exists

The project is still defining its long-term licensing and financing structure. Adopting a broad open-source license or accepting substantial third-party IP prematurely could create avoidable ambiguity around rights, commercialization and future investment.

The current posture is therefore deliberately conservative:

```text
PUBLICLY VISIBLE != OPEN-SOURCE LICENSED
DISCUSSION != IP TRANSFER
PULL REQUEST != AUTOMATIC ACCEPTANCE
PRIVATE CORE REMAINS PRIVATE
```

## Before substantial external code contributions

Korako should explicitly decide and document:

1. the license, if any, for public source components;
2. whether a Contributor License Agreement (CLA), Developer Certificate of Origin (DCO), or another contribution model is appropriate;
3. ownership and licensing of contributed code and documentation;
4. treatment of patents, trademarks and brand assets;
5. company/entity ownership of the relevant IP;
6. how contributions interact with the private canonical runtime.

Until that decision is made, maintainers should prefer critique, issues, test cases, documentation and bounded proof improvements over substantial external implementation.

This is a project contribution policy, not legal advice.
