# Supporting Korako Yolawani

Korako may use GitHub Sponsors as a way to support continued work on the **public Korako ecosystem**, including public documentation, reproducible proof harnesses, benchmarks, community review and selected open components.

## What sponsorship means

A sponsorship is support for ongoing project work.

It does **not** by itself provide:

- equity, shares or ownership in Korako;
- a right to future profits or financial returns;
- ownership of Korako intellectual property;
- access to the private KORA/Korako runtime;
- authority over product, safety or security decisions;
- a guarantee that a requested feature will be implemented.

Investment, equity financing and commercial contracts are separate processes and should not be represented as GitHub sponsorships.

## Transparency rule

Sponsor-facing claims should follow the same evidence discipline used elsewhere in Korako:

```text
PREPARED != EXECUTED != VERIFIED != PUBLICLY REPRODUCED
```

Do not promise production readiness, quantified ROI, delivery dates or capabilities that are not supported by current evidence.

## Funding activation gate

The repository-level Sponsor button should be activated only after the GitHub Sponsors account is approved and its payout, identity/tax and tier configuration is complete.

At that point, the intended repository configuration is:

```yaml
# .github/FUNDING.yml
github:
  - vcheeko
```

This file is intentionally **not activated in this candidate until the Sponsors profile is confirmed live**, so the public repository does not expose a dead or misleading funding link.

## Suggested sponsor framing

Keep tiers simple and contribution-oriented. Possible names:

- **Supporter**
- **Builder**
- **Founding Supporter**

Benefits should be community benefits that can actually be delivered, such as supporter recognition, public project updates or community sessions. Avoid investment-like language, guaranteed outcomes or access that would weaken the public/private boundary.
