# Korako Yolawani — Devil Mode

**Observed:** 2026-10-01

This page records the strongest current reasons **not** to overclaim Korako.

## 1. Mira reliability is not yet proven

The flagship conversational path is still under verification. Physical microphone acceptance and the required repeated end-to-end PASS evidence are incomplete.

**Implication:** voice demos or partial traces must not be presented as production-grade reliability.

## 2. Architecture can become too broad

Korako spans orchestration, state, tools, agents, Human Gates, verification, voice, UI and many life/work domains.

**Failure mode:** building every capability internally creates duplicate infrastructure and slows the one verified journey that matters most.

**Control:** bridge-first, capability radar, sandbox benchmarks, WIP discipline and explicit build-vs-buy evidence.

## 3. Verification can become ceremonial

A Worker/Checker/Auditor model only matters if identities, receipts and evidence are independently inspectable.

**Failure mode:** agents restate one another's claims or write outcome states outside their role boundary.

**Control:** single-writer verification states, independent evidence checks, actor identity checks and fail-closed handling of missing proof.

## 4. Monday orchestration is useful but not the product truth by itself

A board, agent trigger or automation can coordinate work, but it does not prove that the external runtime, GitHub code, browser flow or user journey succeeded.

**Control:** receipts must point to the system where the action actually occurred.

## 5. Revenue research can overfit to visible website quality

An old-looking website does not prove a company will buy a redesign, and public signals do not prove private revenue or budget.

**Control:** separate FACT / INFERENCE / OFFER HYPOTHESIS; prioritize business-value gaps, not aesthetics alone; stop at Human Gate before contact.

## 6. Multi-country expansion can dilute learning

Researching Slovenia, DACH, the US, Australia and other markets avoids single-country dependence but can fragment outreach and positioning.

**Control:** compare markets with the same evidence rubric and test small batches before scaling.

## 7. Time Returned and ROI are not yet defensibly quantified

Korako's thesis includes reducing human-postman work, but a credible manual-vs-Korako baseline still requires real paired measurements.

**Control:** no invented time-saved claims.

## 8. External validation remains limited

Independent third-party reproduction, real-user retention and paid conversion are still missing from the public proof story.

**Control:** treat these as explicit milestones, not implied traction.

## 9. Capability choice changes over time

The best agent, model, tool or orchestrator depends on task, cost, privacy, latency and evidence quality.

**Control:** do not declare a universal winner. Re-run current benchmarks and preserve vendor neutrality.

## 10. Founder attention is a real bottleneck

The project can generate more parallel ideas than one person can safely review.

**Control:** AUTO SAFE PARALLEL for reversible research/preparation; Human Gates only for consequential actions; critical-path WIP remains constrained.

## Bottom line

The strongest public position is not "Korako already does everything." It is:

> Korako is building a governed spine for complex AI-assisted work, and it is deliberately refusing to call the flagship journey verified until the required evidence exists.
